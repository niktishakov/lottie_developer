# Lottie Developer

Мак-приложение + MCP-сервер `lottie-developer` для разработки Lottie-анимаций через Claude.
Дизайнер даёт ассеты и промт в чат, Claude делает версии через MCP, дизайнер смотрит и комментирует в приложении.

## Роли

| Кто | Что делает |
|---|---|
| Дизайнер | кидает в чат zip / папку / файлы, пишет что должно двигаться; смотрит в приложении, ставит комментарии на кадры |
| Claude | собирает сцену, делает версии, проверяет рендером, читает комментарии, исправляет |
| Приложение | показывает изменения из MCP сразу (live-sync), таймлайн, слои, сравнение версий, экспорт |

## Рабочий цикл (скилл `/animate` — подробно)

1. **Ассеты → проект.** zip/папка: `create_project(bundle: path)`. Одиночные файлы: `create_project(images: [...])`, `add_svg`, `add_image`.
   У каждого проекта есть папка ассетов (вкладка Assets в приложении): `list_assets` — пути к оригиналам (открывай файлы, чтобы посмотреть), какие слои из них сделаны;
   `add_assets` — положить файлы/zip в папку, `place_asset` — поставить в сцену, `delete_asset` — в Корзину. Дизайнер может класть файлы туда сам (Finder или перетаскиванием).
   Картинку, вставленную в чат скриншотом, в файл записать нельзя — попроси файл (перетащить в чат) или путь.
2. **Сцена.** `get_geometry` → `render_frame` (посмотри сам!) → `place_layer` / `rename_layer`, пока раскладка не совпадёт с макетом.
   Импорт ставит SVG группой по центру — почти всегда её надо передвинуть.
3. **Версия.** `get_guide` (схема и правила) → `validate_spec` → `create_version` с `prompt` (что задумано) и `note` (что именно сделал).
   Точная правка движения — `set_keyframes`.
4. **Проверка.** `render_frame(count: 6..8)` — смотри кадры до того, как сказать «готово». Нет рендера — нет «готово».
5. **Обратная связь.** `get_feedback` — комментарии дизайнера (версия, кадр, слой, текст). Исправил → `resolve_feedback` с ответом.
6. **Отдача.** `export` (JSON) или экспорт `.lottie`/GIF в приложении.

## Правила

- Ничего не удаляй (проекты, версии, слои) без явной просьбы дизайнера. Откат — `restore_version`, а не удаление.
- Каждая версия — с `note`: одной строкой, что поменялось. Это история для дизайнера.
- Слои после импорта называются `path-3`, `rect-2` — переименуй значимые (`rename_layer`) до анимации.
- Слои-картинки (растр и SVG-элементы с blur/масками) анимируются только трансформами: fade, slide, scale, rotate, followPath…; `drawOn`, `recolor`, `addFill/Stroke` к ним не применимы.
- Группа (null-слой с именем файла) двигает все свои части — анимируй группу, если двигается файл целиком.
- `show_in_app` с `frame` и `layer` — показать дизайнеру конкретное место.
- Общение с дизайнером — простыми словами, без внутренних терминов (spec, null-слой) без нужды.

## Сборка и запуск

| Что | Команда |
|---|---|
| MCP-сервер (Claude подключает сам через `.mcp.json`) | `bin/lottie-mcp --build` (первый раз ~1 мин) |
| Мак-приложение | `xcodebuild -project LottieDeveloper.xcodeproj -scheme LottieDeveloperMac -derivedDataPath build/dd build`, затем `open build/dd/Build/Products/Debug/LottieDeveloperMac.app` |
| Тесты | `xcodebuild -project LottieDeveloper.xcodeproj -scheme LottieCompilerTests -derivedDataPath build/dd test` |
| После добавления файлов | `xcodegen generate` |

## Устройство

| Папка | Что внутри |
|---|---|
| `Sources/AI/Spec` | AnimationSpec (DSL) + детерминированный `LottieCompiler` |
| `Sources/Shared` | общее для приложения и MCP: рендер кадров, правки слоёв, картинки, сборка сцены, импорт пачек, SVG DOM |
| `Sources/macOS` | приложение: `ProjectStore` (данные на диске), редактор, плеер |
| `Sources/MCP` | `lottie-mcp`: протокол и инструменты |
| Данные | `~/Library/Application Support/LottieDeveloperMac/projects/<id>/` — `project.json`, `static.json`, `versions/` |

Коммиты: префикс `LD-<номер>:`.
