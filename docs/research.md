## 1. Текущая воронка онбординга

### Общая архитектура

Приложение использует `@AppStorage("hasCompletedOnboarding")` для отслеживания прохождения онбординга. После установки флага в `true` пользователь навсегда попадает в `AnimationLibraryView`. Онбординг показывается ровно один раз — повторного показа нет.

```
Установка --> Онбординг (3 страницы) --> [Paywall?] --> Библиотека
```

### Страница 1: "Ship Lottie Without Surprises"

- **Тип:** информационная (features showcase)
- **Визуал:** логотип приложения (AppLogo, 100x100), заголовок, подзаголовок, 3 фичи с иконками
- **Иконки фичей:** `folder.badge.plus`, `play.circle`, `iphone.and.ipad`
- **Навигация сверху:** "Шаг 1 из 3" (capsule с blur) + кнопка "Пропустить" справа
- **Навигация снизу:** кнопка "Далее" (градиент cyan-blue, full-width, отступ 88pt от низа)
- **Действие "Пропустить":** вызывает `complete()` — мгновенный переход на главный экран, пропуская ВСЕ оставшиеся шаги и пейволл

### Страница 2: "Debug in Seconds"

- **Тип:** информационная (features showcase)
- **Визуал:** SF Symbol `slider.horizontal.3` (64pt, cyan), заголовок, подзаголовок, 3 фичи
- **Иконки фичей:** `gauge.with.dots.needle.33percent`, `arrow.left.and.right`, `star`
- **Навигация:** идентична странице 1 ("Шаг 2 из 3" + "Пропустить" + "Далее")
- **Действие "Пропустить":** та же функция `complete()` — полный пропуск

### Страница 3: "See It Working First"

- **Тип:** интерактивная демо-страница
- **Визуал:** темный градиентный фон (dark blue), заголовок и подзаголовок белым, canvas с демо-анимацией (ракета), декоративный cyan blur-circle
- **Элементы управления:**
  - Кнопка play/pause (58pt, градиент cyan-blue)
  - 7 пресетов скорости: 0.25x, 0.5x, 0.75x, 1.0x, 1.5x, 2.0x, 3.0x (capsule pills)
- **CTA:** "Continue to Library" / "Продолжить в библиотеку" — градиентная кнопка внизу
- **Навигация:** БЕЗ кнопки "Пропустить", БЕЗ кнопки "Далее", БЕЗ индикатора шага
- **Индикатор страниц (dots):** скрыт на этой странице (`indexDisplayMode: .never`)

### Механизм триггера пейволла

Пейволл вызывается автоматически через систему подсчета взаимодействий:

```swift
@State private var demoInteractions = 0
@State private var hasAutoPresentedPaywall = false

private func registerDemoInteraction() {
    guard page == .ready else { return }
    guard !purchaseStore.isPro else { return }
    guard !showPaywall else { return }
    guard !hasAutoPresentedPaywall else { return }

    demoInteractions += 1
    guard demoInteractions >= 4 else { return }

    hasAutoPresentedPaywall = true
    showPaywall = true
}
```

**Условия показа пейволла:**
- Только на странице `.ready` (третья)
- Пользователь НЕ является Pro
- Пейволл еще НЕ показывался (`hasAutoPresentedPaywall == false`)
- Накоплено >= 4 взаимодействий (play/pause ИЛИ смена скорости)
- Пейволл показывается **максимум один раз** за сессию онбординга
- Показ через `.sheet(isPresented:)` — пользователь может свайпнуть вниз для закрытия

### Пейволл (PaywallView)

- **Презентация:** `.sheet` с `.presentationDetents([.large])`, кнопка "Отмена" в toolbar
- **Структура:** header --> features --> pricing --> CTA --> reassurance --> restore --> legal
- **Продукты:** загружаются через StoreKit 2, предвыбран Lifetime
- **Ценовые карточки:** Lifetime ($4.99, NonConsumable) и Annual ($1.99/yr, RecurringSubscription)
- **Lifetime выделен:** бейдж "Best Value" / "Лучшая цена" сверху
- **CTA меняется:** "Unlock for $4.99" или "Subscribe for $1.99/year" в зависимости от выбранной карточки
- **Dismiss:** кнопка "Отмена" или свайп вниз (заблокирован во время покупки)
- **После dismiss:** пользователь возвращается на страницу 3 и может нажать "Continue to Library"

### Воронка в виде последовательности

```
Установка
  |
  v
Страница 1 --[Пропустить]--> Библиотека (пейволл НЕ показан)
  |
  [Далее]
  v
Страница 2 --[Пропустить]--> Библиотека (пейволл НЕ показан)
  |
  [Далее]
  v
Страница 3
  |
  |--[CTA "Continue to Library" до 4 тапов]--> Библиотека (пейволл НЕ показан)
  |
  |--[4+ тапа play/pause/speed]--> Пейволл (sheet)
  |     |
  |     |--[Покупка]--> dismiss --> Библиотека (Pro)
  |     |--[Отмена/свайп]--> Страница 3 --> [CTA]--> Библиотека (Free)
  |
  v
Библиотека
```

## 3. Проблемы конверсии

### 3.1. Отсутствие аналитики (критическая)

**Проблема:** В Privacy Policy явно указано: "The App does not use any analytics services or tracking tools." Приложение принципиально не собирает никакие данные.

**Последствия:**
- Невозможно измерить конверсию ни на одном этапе воронки
- Невозможно понять, где пользователи отваливаются
- Невозможно рассчитать ARPU, LTV, retention
- Невозможно валидировать любые изменения — все оптимизации будут вслепую
- Невозможно провести A/B тесты
- Нет данных для принятия решений о ценообразовании

**Оценка влияния:** Это фундаментальный блокер для любой оптимизации конверсии. Без метрик все остальные рекомендации в этом документе невозможно проверить.

### 3.2. Кнопка "Пропустить" слишком доступна

**Проблема:** На страницах 1 и 2 кнопка "Пропустить" (`Skip`) расположена в правом верхнем углу и вызывает `complete()` — полный пропуск онбординга, включая пейволл.

**Код:**
```swift
Button {
    complete() // hasCompletedOnboarding = true
} label: {
    Text(L10n.string("onboarding.skip"))
        .font(.subheadline.weight(.medium))
        .foregroundStyle(.secondary)
}
```

**Последствия:**
- Пользователь может пропустить весь онбординг за 1 тап на первом же экране
- Все 3 страницы контента и пейволл полностью обходятся
- Нет промежуточного варианта (skip to paywall, skip to demo)
- Типичные "скипперы" — опытные пользователи, которые часто становятся наиболее платежеспособными

**Оценка влияния:** Высокое. По индустриальным данным, 40-60% пользователей нажимают Skip на онбординге. Каждый из них не увидит пейволл.

### 3.3. CTA страницы 3 обходит пейволл

**Проблема:** Кнопка "Continue to Library" на странице 3 вызывает `onComplete()`, что ставит `hasCompletedOnboarding = true` и ведет прямо в библиотеку — без показа пейволла.

```swift
Button {
    onComplete() // --> hasCompletedOnboarding = true --> Библиотека
} label: {
    Text(L10n.string("onboarding.demo.cta.continue"))
}
```

**Последствия:**
- Пользователь, который пришел на страницу 3, видит привлекательную CTA "Продолжить в библиотеку" и нажимает ее
- Если он сделал менее 4 взаимодействий с демо, пейволл НЕ показался
- Многие пользователи (особенно целеустремленные, пришедшие за конкретным функционалом) нажмут CTA сразу

**Оценка влияния:** Критическое. Это основная утечка в воронке — CTA спроектирована так, что она КОНКУРИРУЕТ с пейволлом, а не ведет к нему.

### 3.4. Скрытый и непредсказуемый триггер пейволла

**Проблема:** Пейволл показывается только после >= 4 взаимодействий (play/pause или смена скорости) на странице 3. Этот порог:
- Не визуализирован для пользователя (нет progress bar к "разблокировке")
- Высок для первого контакта (многие нажмут play, посмотрят анимацию и нажмут "Continue")
- Конкурирует с CTA "Continue to Library", которая доступна с первого момента

**Типичный сценарий:**
1. Пользователь попадает на страницу 3
2. Видит play (анимация уже проигрывается — `isPlaying = true` по дефолту!)
3. Замечает CTA "Continue to Library"
4. Нажимает CTA после 0-1 взаимодействий
5. Попадает в библиотеку, никогда не увидев пейволл

**Особая проблема:** Анимация запускается автоматически (`playback.isPlaying = true` в `resetDemoPlayback()`). Пользователю НЕ НУЖНО нажимать play, чтобы увидеть демо. Это снижает число взаимодействий.

**Оценка влияния:** Критическое. Подавляющее большинство пользователей не достигнет порога в 4 взаимодействия.

### 3.5. Отсутствие urgency и scarcity на пейволле

**Проблема:** Пейволл не содержит никаких элементов срочности:
- Нет ограниченного по времени предложения
- Нет вводной скидки
- Нет free trial с дедлайном
- Нет счетчика ("осталось X мест" — не подходит для приложений, но есть аналоги)
- Цена статична и не привязана к промо-периоду

**Оценка влияния:** Среднее. Urgency повышает конверсию на 10-30% по индустриальным данным для мобильных пейволлов.

### 3.6. Фичи на пейволле не дифференцируют Free vs Pro

**Проблема:** Список фичей на пейволле:
1. "Unlimited imports from Files, URL, Clipboard"
2. "Frame-accurate speed and playback range controls"
3. "Save favorites, rename files, and keep your QA flow fast"

Пользователь на этом этапе НЕ знает, что доступно бесплатно, а что — только в Pro. Feature 2 он уже частично видел в демо. Нет визуального сравнения (таблица Free vs Pro).

**Оценка влияния:** Среднее. Неясность блокирует принятие решения о покупке.

### 3.7. Годовая цена ($1.99/год) каннибализирует Lifetime ($4.99)

**Проблема:** Две ценовые опции создают каннибализацию:
- Lifetime: $4.99 (единоразово)
- Annual: $1.99/год
- Lifetime окупается за 2.5 года по сравнению с Annual

**Риски:**
- Пользователь, готовый заплатить $4.99, может выбрать $1.99 и уйти через год (или не продлить)
- Annual создает "стоимость проверки" — $1.99 кажутся безопасной ставкой, но annual churn в категории utility-приложений составляет 60-80%
- Разница в цене слишком мала для двух опций — нет "якорного" дорогого варианта
- При этом Lifetime выделен как "Best Value", но на практике Annual дешевле в первый год

**Оценка влияния:** Среднее. Dual pricing без четкой стратегии снижает средний чек.

### 3.8. Демо-анимация не демонстрирует ценность продукта

**Проблема:** Демо-анимация — это файл `demo_animation.json` (ракета). Это generic-анимация, которая:
- Не показывает реальный use case (отладка сложной multi-layer анимации)
- Не демонстрирует проблемы, которые решает приложение (сломанные кадры, проблемы тайминга)
- Не создает "aha moment" — пользователь видит ракету и думает "ок, симпатично", а не "это решит мою проблему"

**Оценка влияния:** Среднее. Правильная демо-анимация может значительно повысить вовлеченность на странице 3 и, как следствие, число взаимодействий и показов пейволла.

### 3.9. Несогласованность RU-локализации

**Проблема:** "Debug in Seconds" переведено как "Дебаг за минуты" (минуты вместо секунд). Это меняет смысл обещания с "мгновенно" на "быстро, но придется подождать".

Другие проблемы RU-локализации:
- "Подписку можно управлять" — грамматическая ошибка (правильно: "подпиской")
- "Покадровая проверка со скоростью" — неоднозначная конструкция
- "контролами" — ненатуральная калька с английского
- "Релизьте" — стилистически спорный неологизм

**Оценка влияния:** Низкое-среднее. Зависит от доли RU-пользователей, но некачественная локализация снижает доверие и профессиональное восприятие приложения.

## 4. Гипотезы для A/B тестов

### Гипотеза 1: Показ пейволла детерминированно (между страницей 2 и демо ИЛИ перед библиотекой)

**Что менять:** Вместо триггера по 4 взаимодействиям — показывать пейволл детерминированно. Два варианта:
- **Вариант A:** Пейволл между страницей 2 и страницей 3 (paywall-first, demo-after)
- **Вариант B:** Пейволл после страницы 3, перед библиотекой (CTA "Continue" ведет на пейволл, а не в библиотеку)

**Ожидаемое влияние на метрики:**
- Paywall impression rate: с предполагаемых ~15-25% до 100% (для дошедших до этого шага)
- Paywall conversion rate: может снизиться (показ "холодным" пользователям), но общая конверсия (impressions x CR) должна вырасти
- Skip rate на страницах 1-2 может увеличиться, если пользователи узнают про пейволл

**Приоритет: ВЫСОКИЙ**
Это наиболее высокоэффективное изменение. Текущая архитектура позволяет большинству пользователей полностью обойти пейволл.

---

### Гипотеза 2: Убрать кнопку "Пропустить", оставить только свайп назад

**Что менять:** Удалить кнопку "Skip"/"Пропустить" на страницах 1-2. Оставить навигацию через "Далее" и стандартный swipe TabView.

**Ожидаемое влияние на метрики:**
- Onboarding completion rate (до страницы 3): рост на 30-50% (по бенчмаркам подобных изменений)
- Paywall impression rate: пропорциональный рост
- Retention: может незначительно снизиться (фрустрация "застрявших" пользователей), но трение минимально (всего 2 тапа "Далее")

**Риски:**
- App Store Review может запросить возможность пропуска, если онбординг блокирует использование
- Решение: оставить swipe на TabView как альтернативный способ быстрой навигации

**Приоритет: ВЫСОКИЙ**

---

### Гипотеза 3: Изменить CTA страницы 3 с "Continue to Library" на "Unlock Pro" / "Start Free Trial"

**Что менять:** CTA на странице 3 вместо перехода в библиотеку открывает пейволл.

**Варианты текста:**
- "Unlock Pro" / "Разблокировать Pro"
- "Start Free Trial" / "Начать бесплатный пробный период" (если добавить trial)
- "Continue" (нейтральный, но ведет на пейволл)

**Ожидаемое влияние на метрики:**
- Paywall impression rate: значительный рост (каждый нажавший CTA увидит пейволл)
- Conversion rate: зависит от текста. "Unlock Pro" может отпугнуть, "Continue" — мягче
- Если добавить trial: trial start rate ~40-60%, trial-to-paid ~30-50%

**Приоритет: ВЫСОКИЙ**

---

### Гипотеза 4: Снизить порог взаимодействий с 4 до 2 (если оставить текущую механику)

**Что менять:** Изменить `demoInteractions >= 4` на `demoInteractions >= 2`.

**Ожидаемое влияние на метрики:**
- Paywall impression rate: рост (больше пользователей достигнут порога)
- User experience: менее агрессивно, чем полное удаление порога, сохраняет "earn the paywall" подход

**Ограничения:** Это полумера. Даже с порогом 2, пользователь может нажать CTA до первого взаимодействия. Гипотеза 3 решает проблему радикальнее.

**Приоритет: СРЕДНИЙ** (актуально, только если гипотезы 1 и 3 отклонены)

---

### Гипотеза 5: Добавить социальное доказательство на пейволл

**Что менять:** Добавить блок между header и features:
- Рейтинг из App Store (например, "4.9 из 200+ оценок")
- Цитата пользователя
- Логотипы компаний (если есть известные пользователи)
- Число пользователей ("Используют 5000+ разработчиков")

**Ожидаемое влияние на метрики:**
- Paywall conversion rate: +10-25% (по бенчмаркам social proof на paywall)
- Trust: значительный рост, особенно для нового приложения без репутации

**Ограничения:** На старте может не быть достаточно отзывов. Можно использовать "Featured by Apple" (если применимо) или beta-тестеров.

**Приоритет: СРЕДНИЙ**

---

### Гипотеза 6: Один вариант цены (только Lifetime) vs текущие два

**Что менять:** Убрать Annual ($1.99/год), оставить только Lifetime ($4.99).

**Ожидаемое влияние на метрики:**
- Revenue per paying user: рост (все платят $4.99 вместо части на $1.99)
- Conversion rate: может снизиться (нет "дешевого входа"), но выручка на пользователя выше
- Paradox of choice: одна опция упрощает принятие решения
- Долгосрочно: нет проблемы annual churn

**Альтернативный вариант:** Оставить обе опции, но сделать Annual дороже ($3.99/год), чтобы Lifetime ($4.99) был очевидно выгоднее.

**Приоритет: СРЕДНИЙ**

---

### Гипотеза 7: Заменить демо-анимацию на сложную multi-layer анимацию с видимыми проблемами

**Что менять:** Вместо generic ракеты использовать:
- Сложную UI-анимацию с несколькими слоями (типичная для реального продакшена)
- Анимацию, где на определенных скоростях видны артефакты или тайминг-проблемы
- Анимацию, которая демонстрирует, зачем нужен frame-by-frame control

**Ожидаемое влияние на метрики:**
- Page 3 interaction count: рост (пользователь захочет исследовать артефакт)
- Paywall impression rate: рост (больше взаимодействий --> выше шанс достичь порога)
- "Aha moment" creation: пользователь поймет ценность продукта через опыт

**Приоритет: НИЗКИЙ** (требует создания или подбора специальной анимации, менее предсказуемый эффект)

## 5. Рекомендации по метрикам

### Ключевые метрики воронки (Primary)

| Метрика | Описание | Формула | Цель |
|---------|----------|---------|------|
| **Onboarding Completion Rate** | Доля пользователей, дошедших до конца онбординга | Дошедшие до библиотеки / Все новые пользователи | > 80% |
| **Per-Page Completion Rate** | Доля пользователей, прошедших каждую страницу | Перешедшие на стр. N+1 / Видевшие стр. N | > 85% на каждую |
| **Skip Rate (per page)** | Доля нажавших "Пропустить" на каждой странице | Нажавшие Skip на стр. N / Видевшие стр. N | < 15% |
| **Paywall Impression Rate** | Доля пользователей, увидевших пейволл | Видевшие PaywallView / Все новые пользователи | > 70% (цель) |
| **Paywall Conversion Rate** | Доля купивших из видевших пейволл | Совершившие покупку / Видевшие PaywallView | > 5% (индустриальный ориентир) |
| **Paywall Conversion by Product** | Конверсия по каждому продукту | Купившие Lifetime / Видевшие пейволл; Купившие Annual / Видевшие пейволл | -- |

### Метрики вовлеченности (Secondary)

| Метрика | Описание | Как собирать |
|---------|----------|--------------|
| **Page 3 Interaction Count Distribution** | Распределение числа тапов (play/pause/speed) на странице 3 | Гистограмма: 0, 1, 2, 3, 4+ тапов |
| **Time Spent per Page** | Время на каждой странице онбординга | Timestamp при входе и выходе с каждой страницы |
| **Demo Play/Pause Ratio** | Сколько раз нажимали play vs pause | Счетчик событий |
| **Speed Preset Usage** | Какие пресеты скорости популярны | Счетчик по каждому пресету |
| **Paywall Scroll Depth** | Насколько далеко прокручивают пейволл | ScrollView offset tracking |
| **Paywall Dismiss Method** | Как закрывают пейволл (кнопка Cancel vs свайп) | Событие при dismiss с указанием метода |
| **Product Selection Pattern** | Сколько раз переключают между Lifetime и Annual | Счетчик переключений |

### Метрики бизнеса (Business)

| Метрика | Описание | Источник |
|---------|----------|---------|
| **ARPU (Average Revenue Per User)** | Средний доход на пользователя | Общая выручка / Все пользователи |
| **ARPPU (Average Revenue Per Paying User)** | Средний доход на платящего пользователя | Общая выручка / Платящие пользователи |
| **Trial-to-Paid Conversion** | Конверсия из триала в платную подписку (если добавить trial) | Подписавшиеся / Начавшие trial |
| **Annual Renewal Rate** | Доля пользователей, продливших годовую подписку | Продлившие / Все с Annual |
| **Revenue per Product** | Доход по каждому продукту | App Store Connect |
| **Refund Rate** | Процент возвратов | App Store Connect |
| **Day 1 / Day 7 / Day 30 Retention** | Возвращаемость пользователей | Активные на день N / Все установки |

### Технические метрики

| Метрика | Описание | Зачем |
|---------|----------|-------|
| **StoreKit Product Load Time** | Время загрузки продуктов из StoreKit | Долгая загрузка может заблокировать показ цен на пейволле |
| **StoreKit Load Failure Rate** | Частота ошибок загрузки продуктов | Код включает 3 попытки с retry — важно знать, как часто все 3 fail |
| **Purchase Error Rate** | Частота ошибок покупки | Для понимания технических потерь конверсии |
| **Onboarding Animation Load Failure** | Частота недоступности демо-анимации | В коде есть fallback UI "Demo animation unavailable" |

### Рекомендуемый стек аналитики

**Минимальный набор (MVP):**
- **TelemetryDeck** — privacy-first аналитика, совместимая с политикой конфиденциальности приложения ("no personal data"). Не требует consent banner
- Либо **Firebase Analytics** — более мощный, но потребует обновления Privacy Policy

**Расширенный набор:**
- **RevenueCat** — для детальной аналитики монетизации (paywall conversion, LTV, churn)
- **Amplitude/Mixpanel** — для воронок и когортного анализа
- **PostHog** — self-hosted вариант для максимальной privacy

**Важно:** Текущая Privacy Policy явно заявляет об отсутствии аналитики. Добавление любого SDK потребует обновления Privacy Policy и, возможно, App Tracking Transparency (ATT) prompt. TelemetryDeck не требует ATT, так как не использует device identifiers.
